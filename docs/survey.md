## §2. 영문 팬패치 오라클 (확정)

- 섹터 유저데이터 비교: **변경 30 / 35,823**

- → **텍스트·폰트 변경이 `/2` 한 파일에 모여 있다**

## §3. ★★적재 베이스 = `0x0600E800` (정정)

전작 기록의 `0x06010000` 은 **틀렸다.** 무기 화면 스테이트(RZIP → Mednafen 섹션 `WorkRAMH`, **swap16**)에서
`/2` 선두 256바이트를 찾아 `0x0600E800` 확정. 「標準的な火砲」이 RAM `0x0602195A` ↔ 파일 `0x1315A` 로 일치.

**파일 오프셋 = 주소 − 0x0600E800.**

이 한 값이 틀려서 포인터 해석이 전부 어긋나 있었다. 바로잡자 JP↔EN 대응 **191쌍**이 즉시 나왔다.

## §4. 텍스트 (확정)

- 평문 **cp932**, 널 종단, 참조 = **BE32 절대주소**
- 제어 토큰: `{0A}{0B}`(항상 쌍, 287회 = 줄바꿈) / `{01}` 31회 / `{06}` 27회 (뒤 둘은 미규명)
- 코퍼스 = **276문자열 / 14,188 B / 9,311자 / 고유문자 685종**, 영문 대응 **160개**
- 산출: `work/trans/text_jp.tsv` (`id off addr bytes chars nrefs refs en jp`) — **참조 위치 포함**이라 재배치 가능
- 추출 도구 `tools/extract_text.py`

⛔ **맹목 스캔 금지.** 폰트 글리프와 SH-2 코드가 우연히 한자로 디코드돼 노이즈가 진짜보다 많다(683 대 271).
→ **포인터 참조를 씨앗으로 구역 확장**. 폰트 밖 미포함 3구역도 직접 열어 전부 코드 쓰레기임을 확인.

## §5. ★★폰트 완전 해독 (확정)

**글리프 = 11×11 픽셀 / 22바이트** (한 행 2바이트 × 11행, 상위 11비트 사용).

뱅크 서술자 배열이 파일 **`0x6280`** 에 `[BE32 폰트포인터][BE32 표포인터]` × 3.

| 뱅크 | 폰트 | 표 | 크기 | 글리프 | 담당 |
|---|---|---|---|---|---|
| A | `0x0167C4` | `0x3B71C` (20레코드) | 11,572 B | **526** | 0x8140~ 기호·가나·그리스·키릴·괘선 |
| B | `0x0194F8` | `0x3B76E` (32레코드) | 65,232 B | **2,965** | 0x889F~ 한자 **제1수준** |
| C | `0x0293C8` | `0x3B7F0` (37레코드) | 74,580 B | **3,390** | 0x989F~ 한자 **제2수준** |

합계 6,881글리프 / 151,382 B = 모듈의 60%.
뱅크B 가 2,965 = JIS 제1수준 한자 정확히 그 수 → 구조가 스스로 검산된다.

**매핑**: 표 = `[BE16 레코드수]` + `[BE16 코드][BE16 인덱스]` 반복.
`인덱스 = 레코드값 + (레코드 코드부터 대상 코드까지 «유효 SJIS» 개수)`
(트레일 0x7F 건너뛰고, 0xFC 넘으면 다음 리드바이트 0x40 으로).

검증: `　、。０１２ＡＢａｂぁあいうえおアイウエオ亜唖娃阿標準的火砲威力連射能` 전부 정확히 렌더.

### 삽질 기록 (재발 방지)
폰트 베이스를 **통계로 찾으려다 여러 차례 실패**했다 — 참조 폰트(MS Gothic) 상관·IoU·잉크 프로파일·
작은가나/큰가나 쌍 유사도 전부 무의미했다. 원인 둘:
①글리프가 **22 B** 인데 32 B 로 가정했고 ②베이스가 **32정렬이 아니다**(`0x167C4`).
정답은 **뱅크 서술자 배열**이었고, 그건 「표를 가리키는 리터럴 3개가 간격 8」이라는 관찰에서 나왔다.

## §6. 영문팀이 덮어쓴 구역 = 폰트 (확정)

`0x179B8~0x1DDB3` (25,595 B):

| 대상 | 훼손 |
|---|---|
| 뱅크A 인덱스 **208(`ｚ`)~525** | 히라가나·가타카나·그리스·키릴·괘선 전멸 |
| 뱅크B 인덱스 **0~846** | 한자 제1수준 앞 847자 |
| 뱅크C | **0개** |

경계가 `ｚ` 바로 뒤(=`ぁ` 209)다. 영문에 필요한 건 기호·숫자·전각로만(0~208)까지라 딱 거기서 잘랐다.
→ **내 폰트 해독의 독립 검산**이 된다(2바이트 단위로 일치).

## §7. 한글화 관점 초기 판정

본문 사용 문자: 1바이트 39 / 뱅크A 179 / 뱅크B 475 / **뱅크C 11**.

| 뱅크 | 슬롯 | 사용 | 여유 |
|---|---|---|---|
| A | 526 | 179 | 347 |
| B | 2,965 | 475 | 2,490 |
| C | 3,390 | **11** | **3,379** |

여유 **6,216슬롯 / 136,752 B**. 완성형 2,350자를 넣고도 절반 이상 남는다.
**뱅크C 를 한글로 쓰면 제2수준 한자 코드를 그대로 쓰므로 매핑표도 안 건드려도 된다.**
영문패치가 뱅크C 를 안 건드려 원본이 온전한 것도 유리.

## §8. 다음 판정 대상
